Día 3: arquitectura por capas e import-linter

Propósito y preparación

Audiencia. Estudiantes que ya poseen reglas de catálogo. Prerrequisitos. Funciones, paquetes, anotaciones y Git básico. El nombre de este archivo contiene un espacio por autorización explícita; no se renombra. El objetivo es proteger el dominio de las dependencias de interfaz e infraestructura (O4).

Resultados de aprendizaje

  1. Distinguir responsabilidades de domain, application, infrastructure y ui.
  2. Crear un paquete con __init__.py, anotaciones, docstrings y un puerto Protocol.
  3. Aplicar args, kwargs y parámetros keyword-only solo cuando aclaren un caso de uso.
  4. Ejecutar e interpretar el gate obligatorio de import-linter desde la raíz del proyecto.

Conceptos esenciales

Una capa no es una carpeta decorativa: controla qué conocimiento puede atravesarla. El dominio contiene reglas y tipos; no importa SQLite, Tkinter ni comandos de terminal. La aplicación coordina casos de uso; infraestructura implementará detalles más adelante; la UI traduce eventos a casos de uso. La dirección permitida es ui → application → domain; la infraestructura puede implementar puertos de application o domain, pero ni el dominio ni la aplicación importan infraestructura o UI.

Un paquete es una carpeta con __init__.py; las importaciones absolutas hacen visible el límite. Protocol expresa la forma que necesita el caso de uso, no una clase concreta. La inyección entrega una implementación desde fuera, por lo que una prueba puede usar una colección en memoria. Use keyword-only cuando un argumento opcional de coordinación pueda confundirse; *args y **kwargs no sustituyen un contrato explícito.

ImportanteGate obligatorio: no hay sustituto manual

import-linter debe quedar verde en D3 y D14. La lectura manual ayuda a diagnosticar, pero no reemplaza el gate. En este entorno la herramienta no está instalada: el estado es pendiente/no ejecutado, no verde. Ejecútelo en un entorno autorizado antes de avanzar el gate.

Diseño reproducible del paquete

Desde la raíz del repositorio del estudiante, cree este mínimo funcional:

TEXT
inventario-local/
├── pyproject.toml
└── inventario_local/
    ├── __init__.py
    ├── domain/
    │   ├── __init__.py
    │   └── item.py
    ├── application/
    │   ├── __init__.py
    │   └── ports.py
    ├── infrastructure/
    │   ├── __init__.py
    │   └── memory_repository.py
    └── ui/
        └── __init__.py

Copie esta configuración completa en pyproject.toml. include_external_packages = true hace que sqlite3 y tkinter participen en los contratos: sin esa opción, nombrarlos no prueba que el gate observe esos imports. Los contratos prohíben todas las direcciones que D3 declara, pero conservan los adaptadores legítimos.

TOML
[tool.importlinter]
root_package = "inventario_local"
include_external_packages = true

[[tool.importlinter.contracts]]
name = "domain is pure"
type = "forbidden"
source_modules = ["inventario_local.domain"]
forbidden_modules = [
  "inventario_local.application",
  "inventario_local.infrastructure",
  "inventario_local.ui",
  "sqlite3",
  "tkinter",
]

[[tool.importlinter.contracts]]
name = "application does not select adapters or UI"
type = "forbidden"
source_modules = ["inventario_local.application"]
forbidden_modules = [
  "inventario_local.infrastructure",
  "inventario_local.ui",
  "sqlite3",
  "tkinter",
]

[[tool.importlinter.contracts]]
name = "only UI imports UI"
type = "forbidden"
source_modules = [
  "inventario_local.domain",
  "inventario_local.application",
  "inventario_local.infrastructure",
]
forbidden_modules = ["inventario_local.ui"]

Direcciones permitidas: ui → application → domain e infrastructure → application o infrastructure → domain para implementar o usar un puerto. Por ejemplo, infrastructure.memory_repository puede importar el Protocol de application.ports; no queda accidentalmente excluido. Prohibidas y ejecutadas en D3: domain hacia application/infraestructura/UI/SQLite/Tkinter; application hacia infraestructura/UI/SQLite/Tkinter; e infraestructura hacia UI. No traslade estos contratos a D14 ni invierta flechas para satisfacer el linter.

Ejemplo trabajado: contrato y adaptador en memoria

Salida esperada: application can use the port. MemoryRepository no se convierte en el dominio: es un adaptador reemplazable que cumple el contrato.

Ejemplo trabajado: firmas y funciones como valores

*args reúne argumentos posicionales y **kwargs reúne opciones nombradas; úselos al adaptar una frontera, no para esconder el contrato de dominio. Una lambda es una función pequeña; un cierre conserva una variable de su contexto. Un decorador recibe una función y devuelve otra; functools.wraps preserva su nombre y docstring. lru_cache memoriza resultados puros repetidos. La unión de diccionarios base | overrides conserva las claves de ambos y da precedencia al valor de la derecha; es útil para opciones de un caso de uso sin mutar base. Este vocabulario de las flashcards se practica aquí; el decorador de reintentos con backoff/jitter sigue siendo complementario y no es una entrega del núcleo.

Salida esperada: function tools and cache hit passed. El segundo llamado conserva el resultado, incrementa un acierto y no vuelve a ejecutar el cuerpo (calls == 1). El cierre no es estado global; la cache es segura aquí porque label_count es pura. No aplique lru_cache a operaciones que leen o cambian inventario.

Práctica guiada: dibujar antes de mover archivos

  1. Cree los cuatro paquetes y sus __init__.py; escriba una importación absoluta por capa y añada un docstring a cada módulo nuevo.
  2. Dibuje las flechas permitidas y marque con una X domain → infrastructure y application → ui.
  3. Redacte el contrato mínimo ItemRepository con save y find.
  4. Escriba una función con *args, **kwargs y una opción keyword-only; explique qué argumento pertenece al contrato y cuál es solo configuración.
  5. Construya un cierre que prefije un nombre y una lambda equivalente; señale qué valor conserva cada uno.
  6. Combine un diccionario base de opciones con un override mediante |; pruebe que la clave repetida toma el valor derecho y que el diccionario base no cambia.
  7. Aplique @wraps a un decorador de trazado y compruebe __name__; llame dos veces a una función pura con los mismos argumentos y pruebe un acierto, un fallo y una sola ejecución del cuerpo con cache_info().
  8. Proponga un test que use MemoryRepository; no cree SQLite todavía.
  9. Revise en parejas: señalen una importación prohibida y una firma donde un parámetro keyword-only hace más explícita la política.

Punto de control. El docente acepta el diagrama solo si domain no depende de UI ni infraestructura y si el par puede explicar dónde se inyecta el repositorio.

Laboratorio: gate de arquitectura de Inventario Local

Objetivo. Preparar el esqueleto, la configuración y la evidencia del gate; no se promete que una herramienta ausente se ejecutó.

  1. En SPEC-001.md, documente el paquete, las flechas permitidas y dos prohibidas.
  2. Cree el layout anterior y el contrato ItemRepository; use el adaptador en memoria.
  3. Desde la raíz del proyecto (donde vive pyproject.toml), ejecute el gate:
BASH
lint-imports
  1. Pasa solo si el comando termina sin contratos rotos; guarde el comando y salida en el recibo. Falla si indica un importador y una importación prohibida: extraiga un Protocol en application.ports, inyéctelo desde UI o infraestructura, vuelva a ejecutar y guarde ambos resultados. No basta borrar una regla de pyproject.toml.
  2. Si lint-imports no existe, registre literalmente pendiente: import-linter no disponible; instálelo solo cuando una autorización posterior lo permita y ejecute el mismo comando. La revisión manual queda como evidencia auxiliar, nunca como verde.

Code Appendix

from dataclasses import dataclass
from typing import Protocol


@dataclass(frozen=True)
class Item:
    """An inventory item owned by the domain."""
    name: str
    quantity: int


class ItemRepository(Protocol):
    """Port required by application use cases."""

    def save(self, item: Item) -> None: ...

    def find(self, name: str) -> Item | None: ...


class MemoryRepository:
    """Small infrastructure adapter used only for the worked example."""

    def __init__(self) -> None:
        self.items: dict[str, Item] = {}

    def save(self, item: Item) -> None:
        self.items[item.name] = item

    def find(self, name: str) -> Item | None:
        return self.items.get(name)


def register_item(repository: ItemRepository, item: Item, *, replace: bool = False) -> None:
    """Store item through the injected port with an explicit optional policy."""
    if repository.find(item.name) is not None and not replace:
        raise ValueError("item already exists")
    repository.save(item)


repository: ItemRepository = MemoryRepository()
register_item(repository, Item("cable", 3))
assert repository.find("cable") == Item("cable", 3)
assert repository.find("keyboard") is None
print("application can use the port")
from functools import lru_cache, wraps


def make_prefix(prefix: str):
    """Return a closure that retains prefix."""
    return lambda name: f"{prefix}:{name}"


def trace(function):
    """Decorate a function while preserving its metadata."""
    @wraps(function)
    def wrapped(*args, **kwargs):
        return function(*args, **kwargs)
    return wrapped


calls = 0


@lru_cache(maxsize=None)
def label_count(*labels: str, **options: int) -> int:
    """Count labels plus an explicit optional offset."""
    global calls
    calls += 1
    return len(labels) + options.get("offset", 0)


label_count.cache_clear()
prefixed = make_prefix("item")
traced_count = trace(label_count)
settings = {"offset": 0} | {"offset": 1, "source": "practice"}
assert prefixed("cable") == "item:cable"
assert traced_count("cable", "mouse", offset=settings["offset"]) == 3
assert traced_count("cable", "mouse", offset=settings["offset"]) == 3
assert traced_count.__name__ == "label_count"
assert settings == {"offset": 1, "source": "practice"}
assert label_count.cache_info().hits == 1
assert label_count.cache_info().misses == 1
assert calls == 1
print("function tools and cache hit passed")
# Variante prohibida: este import rompe la pureza del dominio.
from inventario_local.infrastructure.memory_repository import MemoryRepository
