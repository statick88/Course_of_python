Día 2: reglas, bordes y Propuesta-L04

Propósito y preparación

Audiencia. Estudiantes con la spec y el recibo de D1. Prerrequisitos. Condicionales, bucles, conversión y excepciones básicas. Hoy se ejercitan reglas acumuladas y bordes; Propuesta-L04 es exclusivamente diagnóstica: no tiene nota, no aporta el 40 % de laboratorios ni genera crédito evaluativo. D8 es la única instancia que la califica.

Resultados de aprendizaje

  1. Explicar cómo una condición de borde cambia una regla de negocio.
  2. Implementar validación acumulada mediante if, bucles y excepciones.
  3. Diseñar una matriz de casos para un límite inclusivo 30/30.
  4. Diferenciar break, continue y pass en una lectura de código.

Conceptos esenciales

Además de if y bucles, practique elif, ternario, match, range, enumerate, zip, el else de un bucle y comprehensions. Úselos cuando aclaren el contrato; no para comprimir reglas que requieren evidencia. continue y pass se retienen de las flashcards de control de flujo.

Una regla compuesta separa condiciones que son distintas: tipo, rango y estado. El orden importa cuando una operación puede fallar; convierta antes de comparar y capture solo el error que puede explicar. Un bucle comunica intención: break termina la búsqueda, continue omite la iteración actual y pass reserva sintaxis sin producir una acción.

El límite 30/30 significa que 30 es válido y 31 no. Probar 1 y 30 no demuestra el borde superior; se necesita el trío 29, 30 y 31. La parametrización formal llegará en D8, pero la matriz de hoy hace visible el diseño antes de automatizarlo.

Las anotaciones modernas documentan contratos para el lector y el verificador estático: Optional[T] equivale a T | None; Literal limita los valores declarados; Final expresa que un nombre no debe reasignarse. No son guardas de ejecución: una función aún valida datos cuando cruza una frontera.

Ejemplo trabajado: decisiones y recorrido explícitos

elif hace mutuamente excluyentes las categorías; el ternario sirve para una decisión simple ya validada; match selecciona casos conocidos. range genera posiciones, enumerate añade índice y zip empareja secuencias hasta la más corta. El else de un bucle se ejecuta solo si no hubo break; por eso expresa una búsqueda sin resultado. Una comprehension crea una colección cuando la transformación cabe en una regla legible.

Salida esperada: flow constructs passed. El ternario no reemplaza una cadena de reglas y el else del bucle no equivale al else de un if.

Ejemplo trabajado: tipos que documentan, validación que protege

Salida esperada: modern type contracts passed. Final y Literal ayudan al análisis estático; la excepción demuestra que la protección de frontera sigue siendo explícita en ejecución.

Ejemplo trabajado: aceptar hasta el límite, no más

Salida esperada: boundary matrix passed. La regla no usa una negación ambigua; expresa directamente qué solicitud supera el stock.

def classify_request(requested: int, available: int) -> str:
    """Classify a request with ordered business rules."""
    if requested < 0:
        return "invalid"
    elif requested == 0:
        return "empty"
    return "accepted" if requested <= available else "exceeds"


def first_missing(names: list[str], quantities: list[int]) -> str | None:
    """Return the first missing item or None after a complete search."""
    for position, (name, quantity) in enumerate(zip(names, quantities), start=1):
        match quantity:
            case 0:
                return f"{position}:{name}"
            case _ if quantity < 0:
                raise ValueError("quantity cannot be negative")
            case _:
                continue
    else:
        return None

assert classify_request(0, 30) == "empty"
assert classify_request(30, 30) == "accepted"
assert classify_request(31, 30) == "exceeds"
assert first_missing(["cable", "mouse"], [2, 0]) == "2:mouse"
assert [number * 2 for number in range(3)] == [0, 2, 4]
print("flow constructs passed")
from typing import Final, Literal, Optional


EMPTY_STATUS: Final = "empty"
StockStatus = Literal["empty", "available"]


def stock_status(quantity: int) -> StockStatus:
    """Return a declared stock state after runtime validation."""
    if isinstance(quantity, bool) or not isinstance(quantity, int):
        raise TypeError("quantity must be an integer")
    if quantity < 0:
        raise ValueError("quantity cannot be negative")
    return EMPTY_STATUS if quantity == 0 else "available"


def find_label(labels: list[str], wanted: str) -> Optional[str]:
    """Return the normalized label or None when it is absent."""
    normalized = {label.strip().lower() for label in labels}
    return wanted.strip().lower() if wanted.strip().lower() in normalized else None


assert stock_status(0) == "empty"
assert stock_status(2) == "available"
assert find_label([" Cable "], "cable") == "cable"
assert find_label(["Cable"], "mouse") is None

def reserve_units(available: int, requested: int) -> int:
    """Return remaining units after an allowed reservation."""
    if requested < 0:
        raise ValueError("requested units cannot be negative")
    if requested > available:
        raise ValueError("requested units exceed available stock")
    return available - requested

def valid_names(names: list[str]) -> list[str]:
    """Return nonempty normalized item names."""
    normalized: list[str] = []
    for name in names:
        clean_name = name.strip()
        if not clean_name:
            continue
        normalized.append(clean_name)
    return normalized

assert valid_names([" cable ", "", "  ", "mouse"]) == ["cable", "mouse"]
